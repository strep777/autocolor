### 4.2 Ollama 模型自动发现（4/4 单测 + UI）

- 设置页填写 Ollama 地址后自动请求 `/api/tags`，无需手工输入模型名；
- 下拉显示模型名 + 体积，刷新按钮可重新读取；
- 选模优先级：当前已选 > `qwen2.5:3b` > `qwen2.5` > `qwen3.5` > `qwen2` > `llama` > `deepseek` > `qwen3` > `qwen`；
- 失败时展示后端返回的中文原因（404 / 超时 / 连接失败），不会静默清空；
- 单元测试覆盖解析、过滤、排序、404、不可达、建议优先级。

真实远程服务返回 3 个模型；界面显示「已读取 3 个本机模型 · 3.1B · Q4_K_M」，自动选中 `qwen2.5:3b`。

### 4.3 真实 Ollama 推荐

| 项 | 结果 |
|---|---|
| 模型 | `qwen2.5:3b`（CPU，远程 11415） |
| 请求 | `POST /api/recommend {hex:"#9FB0BF", mode:"ai", limit:5}` |
| 结果 | `mode="ai"`、8 个候选、5 条 AI 理由、本地 ΔE 排序保留 |
| 耗时 | 20.2 s（UI 实测；含候选筛选与 SQLite 查询） |
| 摘要 | 「目标偏蓝，前两件最接近。」 |
| 色彩解读 | `POST /api/ai/analyze` 约 7–12 s，返回配色与色差风险建议 |
| 备注 | `qwen3:4b` 为 thinking 模型，会先消耗大量 token；`smtek/Qwen3.8-27B:IQ3_XXS` 纯 CPU prefill 过慢（240s 超时）。最终选择 `qwen2.5:3b`。 |

推荐服务保留加权排序：`本地分 × 0.7 + AI 分 × 0.3`，避免小模型把 ΔE 明显更大的商品排到前面。

AI 界面证据见 `screenshots/15-AI推荐-qwen2.5.png`、`screenshots/16-AI色彩解读-qwen2.5.png`。

## 7. 本报告确认修复的缺陷

1. 推荐候选同商品重复 → 按 `product_id` 去重并保留 ΔE 最小色号。
2. 导入 dry-run 恒显示「新增 0 / 更新 0」→ 预判 `action` 并累计 created/updated/skipped。
3. 导入预览渲染对象数组崩溃（React #31）→ `formatPreviewColors` 统一格式。
4. AI 服务函数已改同步但路由仍 `asyncio.run` → 500；改为直接调用。
5. httpx 读取损坏的系统代理导致 `InvalidURL` → `trust_env=False`，并映射为友好错误。
6. intro.js「下一步」被 `:focus` 样式覆盖成灰色 → 提高选择器特异性，禁用态单独处理。
7. 移动端商品表格拥挤 → 默认卡片视图 + 价格/状态不换行。
8. 设置页页脚内容区未撑满 → 主区 `flex-1`，页脚贴底。
9. 批量浮条「5 已选择」语序 → 「已选中 5 项」。
10. 登录页明文展示默认密码 → 改为通用帮助文案，凭据只留在部署文档。
11. 示例色系误判（酒红→棕、柠檬黄→绿）→ 重写 HSL 色系规则并重建种子库。
12. Windows `start.bat` LF 换行导致 cmd 解析错乱 → 转 CRLF，并修正 `.env` 解析与延迟展开。
13. 找色页 AI 按钮在无初始 hex 时永远禁用 → 移除 `if (!hex) return`，进入页面即拉取 AI 状态。
14. `SEED_DEMO=false` 时连管理员都不创建 → 始终 `seed()`，在 seed 内先确保 admin，再按开关决定演示数据。
15. qwen3:4b 在低 `num_predict` 下 content 为空 → 推荐改用 qwen2.5:3b，并提高测试的 max_tokens。
16. Ollama 模型靠手填 → 新增 `/api/ai/ollama/models` 与设置页自动下拉，支持刷新和中文错误提示。
17. 色卡库只按全局 HEX 分组，丢失店铺身份且同店同色重复 → 先按「店铺+色名」、再按「店铺+HEX」双层去重；不同店铺同色保留并标注店铺。
18. 色卡详情弹窗被来源商品的「购买/查看」按钮撑宽，出现横向滚动 → Dialog 网格改 `grid-cols-1`、子项 `min-w-0`，来源行 `flex-wrap`。
19. 商品图上传被 10MB 限制 → 改为分片断点续传（16MB/片），支持 50GB 级会话；服务端按块落盘、磁盘不足返回 507；512MB 内生成 1600px 预览图，更大原图跳过同步解码。
20. 找色页首次上传/粘贴图片不显示 → 画布只在 `imageSrc` 存在时挂载，首次绘制拿不到 canvas；改为画布常驻、空态用 CSS 隐藏，并为 `createImageBitmap` 增加 FileReader 回退，文件/拖拽/粘贴三条路径均已复测。
21. 局域网 HTTP 下复制色值失败 → 非安全上下文没有 `navigator.clipboard`；新增 `copyText` 分级回退：安全上下文用 Clipboard API，否则隐藏 textarea + `execCommand('copy')`。弹窗内的 textarea 必须放在 Radix 焦点域内，且延后 150ms 清理；商品操作下拉菜单关闭会恢复焦点，链接复制需延后 80ms，否则复制内容为空。找色、色卡卡片、色卡详情、商品链接四处均已改为统一实现，并用「复制后 Ctrl+V」验证实际剪贴板内容。

## 8. 已知边界（如实说明）

1. **Docker 未实测**：开发机无 Docker；Dockerfile 已移除前端阶段的 `NODE_ENV=production`（避免 `npm ci` 漏装 devDependencies），补充 `tzdata`，保留 uid 10001 与 healthcheck。
2. **Windows 本机启动**：`start.bat` 在测试中成功启动到 `/api/health`（8012），并能检测 8000 被占用后自动改用 8011；测试工具结束时会回收子进程，故未验证「脚本退出后长期驻留」；双击场景不受此限制。`stop.bat` 只按命令行匹配本项目 uvicorn，不误杀同端口其他服务。
3. **淘宝数据**：未登录只能得到登录跳转页，项目不内置绕过登录的爬虫；当前 25 条真实数据由用户已登录的浏览器会话分批采集，淘宝对连续打开商品会触发登录风控，后续新增商品需重新扫码。图片取色为平均色，非分光测色。
4. **真实 AI**：已接通远程 Ollama 的 `qwen2.5:3b`（CPU）；DeepSeek 与 27B 模型未在最终数据上复验。AI 只做重排与解释，失败自动回退本地。
5. **压测**：未做 5000 色号 / 并发压测。
6. **超大图**：已实测 50GB 上传会话创建与 12MB 分片落盘；未实际上传 50GB 文件（受磁盘与网络时间限制）。超过 512MB 的原图不做同步缩略，浏览器展示/取色仍受本机内存限制。
