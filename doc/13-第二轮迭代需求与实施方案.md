# 13 · 第二轮迭代需求与实施方案

> 版本：v1.2 草案  
> 日期：2026-11-10  
> 状态：文档先行，批准后按任务树实施

## 1. 背景

v1.1 当时已完成 13 个真实淘宝毛布商品、505 条色号、408 个全局色值、332 个店铺色卡，以及局域网部署；本轮完成 6 店同步后扩展到 25 商品 / 863 色号 / 647 色值 / 580 店铺色。用户在实际使用中提出 8 项问题与增强：

1. 找色页切换 tab 后图片和结果丢失；
2. AI 精排不可用；
3. 需要保存每次选取的颜色，并以 tab 展示每个颜色的搜索结果，支持增删改查与全选删除；
4. 色卡库需要按商店、按色号排序；
5. 需要同步淘宝店铺商品，覆盖 6 家店铺的**所有毛布商品和所有颜色**；
6. 商品名称需要体现「商家-类型-长度-色号」，并展示毛布类型；
7. 找色匹配默认免登录，只有设置和商品/色号增删改查需要管理员；
8. 修复「商品中有该色号，却匹配到另一个色号」的算法问题。

本方案先给出架构决策与任务树，再按依赖顺序实施。所有改动完成后统一测试，不边写边宣称完成。

## 2. 关键设计决策

### 2.1 找色页状态：内存级 KeepAlive

- 使用 `frontend/src/lib/finder-store.ts` 保存 `imageSrc / imageSize / hex / mode / onlyClose / result / savedColors`。
- React Router 切换只卸载组件，不刷新页面；模块级 store 在 SPA 生命周期内保留，因此切 tab 回来状态仍在。
- 浏览器刷新或关闭页面会重新加载 JS，模块 store 自然清空，符合“刷新/关闭才清空”。
- 不使用 `sessionStorage`：它刷新后仍存在，不符合需求。
- 上传图片仍只在浏览器本地处理，不上传服务器。

### 2.2 已选颜色 tab

- 数据保存在 `localStorage` 键 `pc-saved-colors-v1`，刷新后仍保留（颜色是用户资产，不属于“页面图片/搜索结果”）。
- 每次取色/预设/手动输入确认后写入一条，按 `hex` 去重；同色更新结果缓存。
- 结果区上方显示颜色 tab：色块 + 色名/HEX + 结果数；点击切换当前颜色并显示该颜色缓存结果。
- “管理颜色”弹窗支持：
  - 勾选、全选、批量删除；
  - 单条重命名（色号名称）；
  - 修改 HEX（重新匹配）；
  - 单条删除。
- 最多保存 30 个颜色，超出提示先清理。

### 2.3 免登录与权限矩阵

| 功能 | 匿名 | 管理员 |
| --- | --- | --- |
| 找色匹配、AI 精排、AI 解读 | ✅ | ✅ |
| 商品库浏览、色卡库浏览、筛选 | ✅ | ✅ |
| 工作台统计 | ✅ 只读 | ✅ |
| 新增/编辑/删除/批量商品 | ❌ | ✅ |
| 色号新增/编辑/删除 | ❌ | ✅ |
| 设置、AI 配置、用户管理、数据导入/同步 | ❌ | ✅ |

- 后端读接口改 `optional_user`；写接口保持 `require_admin`。
- `/api/auth/me` 匿名返回 `{user:null, permissions:{can_manage:false}}`，不再 401，避免每个匿名页面都报错。
- 前端路由：`/finder`、`/products`、`/colors`、`/dashboard` 公开；`/settings`、`/import`、`/users` 需管理员。匿名访问管理员页 → `/finder`。
- 顶栏匿名显示“登录”，登录页成功回跳原地址或 `/finder`。
- 商品/色卡页面匿名隐藏新增、批量、删除、编辑；保留购买链接。

### 2.4 色卡库排序

- 后端 `GET /api/colors?sort=shop|code`：
  - `shop`：店铺名 → 色名 → HEX；
  - `code`：色名 → HEX → 店铺名。
- 前端去掉“按色系/按用量”排序按钮，改为“按商店 / 按色号”分段控件；色系 chips 仍作为筛选。
- 保留店铺身份与同店去重规则。

### 2.5 商品名称与毛布类型

- 新增字段 `pile_length`（毛高/毛长，字符串，如 `4cm`、`7mm`、`3.5cm`）。
- 商品展示名统一为：`【商家-毛布类型-长度-主色号】`，例如：
  - `【八荒九野-珊瑚绒-4cm-海盐】`
  - `【犬物语-弹力毛-7mm-冷灰】`
- 后端 `Product.to_dict()` 返回 `display_name`；前端所有列表/推荐/详情使用 `display_name`。
- 管理员表单增加“毛高/毛长”输入；导入支持 `pile_length`，也可从标题正则提取。
- 毛布类型 `material` 在商品行、推荐卡、详情中显式展示。

### 2.6 淘宝同步

- 新增 `tools/sync_taobao.py`：Playwright + 登录态 profile，扫描 6 家店铺的全部毛布商品与全部 SKU 颜色，输出 `data/import/taobao-sync-<timestamp>.json`。
- 支持 `--shops all|...`、`--profile data/browser-profile`、`--api http://127.0.0.1:8011 --token ...` 三种输出方式。
- 管理端「数据导入」页新增“淘宝同步”卡片：
  - 展示 6 家店铺链接与同步状态；
  - “导入最新采集结果”按钮：读取 `data/import/` 最新 JSON，复用现有预览/导入管线；
  - 说明首次需运行 `python tools/sync_taobao.py --login` 完成扫码。
- 不在 Web 进程内直接启动浏览器（安全、Docker 无 GUI）；采集与导入解耦。
- 每家店铺的颜色去重按“店铺 + 色名 / 店铺 + HEX”，不同店铺允许重复。

### 2.7 AI 精排修复

- 根因：当前配置指向 `smtek/Qwen3.8-27B:IQ3_XXS`（纯 CPU、长提示超时），自动选模又“优先 current”，导致总是保留不可用大模型。
- 修复：
  - `suggest_ollama_model` 优先 `qwen2.5:3b`，再 current，再其他；大参数模型仅作候选。
  - 设置页模型自动刷新时，如果当前模型参数量 > 14B 且存在小模型，默认切到建议模型并提示。
  - AI 推荐候选数从 12 降到 8，提示词要求只返回前 5，减少 CPU prefill。
  - 超时保留 120s；失败回退本地并显示明确原因。
- 验收：设置页显示 qwen2.5:3b，点 AI 精排 20s 内返回 `mode:"ai"`、至少 5 条 reason。

### 2.8 匹配算法修复

- 现状：候选先按 `product_id` 去重，只保留该商品 ΔE 最小的色号；用户看到的商品可能有多个色号，但只展示其中一个，容易产生“商品里明明有这个色号，却给了另一个”的错觉。
- 修复方向：
  1. 候选改为“商品 + 色号”粒度，不再提前按商品去重；
  2. 每个结果明确展示匹配色号与来源商品；
  3. 同一商品最多保留 2 个色号，按 ΔE 排序，避免刷屏；
  4. 先按 HEX 精确匹配，再按 CIEDE2000；
  5. 输出新增 `matched_color` 与 `other_colors`，前端显示“该商品还有 N 个颜色”。
- 同步修正 SKU 取色：从图片中心 45% 区域取平均，降低背景/文字/Logo 干扰。
- 验收：选 `#F55130` 时，如果某商品确有 `#F55130`，必须排第一；没有精确色时，展示实际匹配色与 ΔE，不再显示不同色号却不解释。

## 5. 风险与边界

- 淘宝页面结构/登录态随时变化；同步工具必须可失败重试、保留原始 JSON。
- 6 家店铺商品量可能较大，首次同步耗时较长；颜色上限 200/商品，去重后入库。
- 免登录后推荐接口公开，需限流防刷；写接口仍严格管理员。
- 已选颜色存浏览器本地，不跨设备同步；换浏览器会丢失。
- AI 依赖远程 Ollama 可用性；纯 CPU 大模型不作为默认。
- 50GB 上传只验证了会话与 12MB 分片，未真实传 50GB。


## 6. 实施结果（2026-11-10）

- T24 公开访问：`/finder`、`/products`、`/colors`、`/dashboard` 免登录；`/settings` 需登录，`/import`、`/users` 需管理员；写接口仍 `require_admin`。
- T25 商品命名：`pile_length` 迁移完成，25 个商品（6 家店铺）全部回填或新增；商品名格式【店铺-材质-毛高-色号】，推荐结果按匹配色号生成。
- T26 色卡排序：后端 `sort=shop|code`，前端「按商店 / 按色号」；店铺内先按色名、再按色值双层去重，当前 580 张店铺色卡。
- T27 KeepAlive + 颜色 Tab：Finder 常驻 AppShell，切换页面保留；刷新清空。颜色 Tab 支持自动保存、切换、重命名、全选、批量删除。
- T28 AI：Ollama 模型 qwen2.5:3b，真实 AI 推荐 25.5s 成功；颜色 Tab 场景 29.1s；AI 解读正常。

- T30 淘宝同步：管理端「数据导入 → 淘宝店铺同步」读取 `data/import/taobao-sync.json`，支持状态查询与一键导入。
- T31 数据：当前 25 商品 / 863 色号 / 647 色值 / 580 店铺色；目标 6 店已全部完成（海鲜、犬物、喵喵、Moonfur、MOFUMOFU、万物通行）。
- 未完成边界：淘宝连续 3 个商品后触发登录风控；本轮通过多轮扫码分批抓取，6 家店铺的目标毛布商品已全部入库，但后续新增商品仍需重新扫码采集。

## 7. 追加迭代：色号近色搜索与商家覆盖（2026-11-10）

用户追加要求：色卡库支持输入色号匹配搜索；找色结果中商品库存在的每家店铺至少展示一个颜色。

- 色卡库：`GET /api/colors?q=<HEX>` 识别 3/6 位 HEX（可带 `#`），按 CIEDE2000 与目标色的色差从近到远排序，返回 `distance` 与 `match_level`；卡片显示 `ΔE x.x`，详情显示与搜索色的色差。普通文本仍按色名/HEX/店铺/色系过滤。
- 找色：候选池先为每个有在售商品的店铺保留最近色号，再按色差补足；最终结果再次做店铺覆盖，默认 8 条可覆盖 6 家店铺。`only_close=true` 时只在 ΔE≤3.5 的色号内覆盖，不强行补远色。
- 推荐结果标题使用匹配到的具体色号，商品图片仍为商品主图；色卡详情可从来源商品跳转购买。
