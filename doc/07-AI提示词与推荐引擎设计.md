# AI 提示词与推荐引擎设计

> 目标：同一套业务能力，DeepSeek（云端）与 Ollama + qwen2.5:3b（本地/远程）都能稳定产出**可解析、可校验、不幻觉**的 JSON。
> 位置：默认提示词由后端 `services/prompts.py` 提供，可在「设置 → AI → 提示词」覆盖并恢复默认。

---

## 1. 推荐引擎总体流程

```
用户取色 HEX
  → Lab 转换
  → 候选召回（按筛选条件取全部色号，最多 400 个）
  → 本地 CIEDE2000 排序，取 Top 12 作为候选集
  → [模式=local] 直接返回 Top N
  → [模式=ai] 把「输入色 + 12 个候选」交给模型
        → 模型只做重排、解释、搭配建议
        → 校验返回 id 必须在候选集内、数量≤N、JSON 合法
        → 失败则回退本地 Top N（mode=local_fallback）
  → 返回商品图/色号/ΔE/相似度/购买链接/理由
```

**关键约束：模型不做颜色计算。** ΔE 与相似度由服务端计算，模型只负责业务解释与排序偏好（例如“宠物场景优先低饱和”）。这样 9B 小模型也不会算错数。

---

## 2. 输入数据结构（服务端渲染进提示词）

```json
{
  "input": { "hex": "#C8A27A", "lab": [69.7, 14.9, 27.3], "family": "棕", "name": "焦糖色" },
  "intent": "宠物窝面料选色",
  "candidates": [
    { "id": 101, "name": "焦糖", "hex": "#C9A077", "family": "棕", "material": "珊瑚绒", "shop": "海鲜毛布", "delta_e": 1.24 },
    { "id": 102, "name": "燕麦白", "hex": "#E8DCC8", "family": "米", "material": "法兰绒", "shop": "犬物毛布", "delta_e": 4.8 }
  ]
}
```

- 候选最多 12 条，字段全部截断到 40 字符，防止提示词注入与超长。
- `intent` 来自用户可选输入（如“宠物窝”“秋冬外套”），默认“毛布选色”。

---

## 3. 输出契约（统一）

```json
{
  "summary": "一句话结论（≤40字）",
  "ranking": [
    { "id": 101, "score": 96, "reason": "色差 1.2，几乎同色，适合做主色" }
  ],
  "advice": "搭配与使用建议（≤120字）",
  "caution": "风险提示（≤60字，可为空字符串）"
}
```

服务端校验：
1. `ranking` 必须是数组，长度 1–N；
2. `id` 必须来自候选集，重复 id 去重；
3. `score` 夹取到 0–100；
4. 缺失字段用默认值补齐；
5. 解析失败 → 尝试提取第一个 `{...}` 代码块 → 仍失败则回退。

## 4. DeepSeek 默认提示词（`deepseek-flash-1017` / deepseek-chat 通用）

> 以“Skill”结构书写：角色 → 目标 → 输入 → 规则 → 输出 → 示例 → 自检。DeepSeek 对结构化指令与 JSON 输出较稳，可以给稍复杂的规则。

```text
# SKILL: plush-fabric-color-advisor

## ROLE
你是「毛布选色 · 色研所」的资深面料色彩顾问，服务对象是毛布（法兰绒、珊瑚绒、羊羔绒、短毛绒、摇粒绒）的门店选色员与设计师。你懂色彩科学，也懂绒面织物的工艺限制。

## GOAL
根据用户给出的目标颜色与候选毛布色号，重排候选、解释原因、给出可执行的搭配建议。你不做颜色数值计算，ΔE 由系统提供且可信。

## INPUT (JSON)
{{INPUT_JSON}}

## HARD RULES
1. 只能使用 candidates 中出现的 id，禁止编造商品、色号、价格、链接。
2. 排序首先尊重 delta_e（越小越接近）；若 delta_e 接近（差值 < 1.5），再按使用场景、材质适配、颜色耐看度排序。
3. reason 必须引用具体数字（delta_e 或 hex），并说明适用场景；每条 ≤ 40 字。
4. 不要使用 Markdown、代码块、前后缀说明；只输出一个 JSON 对象。
5. 全部中文；专业词可保留 ΔE、HEX。
6. 若候选整体与目标色差距大（最小 delta_e > 8），必须在 caution 中明确说明“只能作为配色灵感，不能替代原色”。
7. 不承诺色牢度、不掉毛等无法从数据判断的性能；不给出医疗、安全保证。

## SCORING
- 95–100：ΔE ≤ 2，可直接替代
- 85–94：ΔE 2–4，肉眼接近
- 70–84：ΔE 4–8，同色系近似
- 50–69：ΔE 8–12，配色灵感
- < 50：不建议主色使用

## OUTPUT (strict JSON)
{"summary":"...","ranking":[{"id":101,"score":96,"reason":"..."}],"advice":"...","caution":"..."}

## SELF-CHECK (before answering)
- 所有 id 都来自 candidates？
- ranking 按 score 降序？
- 是否只输出了 JSON？
- 是否引用了至少一个 delta_e 数字？
```

**调用参数建议**：`temperature=0.3`、`max_tokens=900`、`response_format={"type":"json_object"}`（DeepSeek 支持时启用；不支持则靠提示词约束）。

## 5. Ollama + qwen2.5:3b 默认提示词

> 3B 模型指令跟随较弱，提示词要**更短、更具体、给完整示例、字段更少**，并明确“不要解释、不要 Markdown”。

```text
你是毛布选色顾问。只输出 JSON，不要解释，不要 Markdown。

任务：从候选色号中选出最适合目标色的毛布，按接近程度排序，并给搭配建议。

目标色：{{TARGET_HEX}}（色系：{{TARGET_FAMILY}}）
用途：{{INTENT}}
候选（id/色名/HEX/材质/色差delta_e）：
{{CANDIDATES_LINES}}

规则：
1. 只能用上面的 id，不能编造。
2. delta_e 越小越接近，优先排前面。
3. reason 要写 delta_e 数字，20 字以内。
4. 最多返回 5 个。
5. 如果最小的 delta_e 大于 8，caution 写“仅作配色灵感”。

只输出这个格式：
{"summary":"一句话","ranking":[{"id":101,"score":96,"reason":"色差1.2，几乎同色"}],"advice":"搭配建议","caution":""}

示例：
输入目标色 #C8A27A，候选 id=101 焦糖 #C9A077 delta_e=1.24。
输出：{"summary":"焦糖最接近","ranking":[{"id":101,"score":96,"reason":"色差1.2，几乎同色"}],"advice":"可做主色，搭配燕麦白包边","caution":""}
```

**调用参数建议**：`temperature=0.2`、`num_predict=600`、`format="json"`（Ollama 结构化输出）、`num_ctx=4096`。

## 6. 自由分析提示词（“AI 分析”按钮）

用于回答“这个颜色适合做宠物窝吗 / 推荐三个搭配色”这类开放问题。输出为纯文本（非 JSON），但仍限制在毛布业务内。

```text
你是毛布选色顾问。基于以下信息，用中文回答用户问题，控制在 180 字内，分 2–3 点。

当前颜色：{{HEX}}（Lab {{LAB}}，色系 {{FAMILY}}）
系统匹配到的近似毛布：{{TOP3_SUMMARY}}
用户问题：{{QUESTION}}

要求：
- 只谈毛布/绒面织物的选色、搭配、使用场景与工艺注意。
- 引用 ΔE 数字说明接近程度。
- 不编造商品与价格；不承诺色牢度等无法验证的性能。
- 结尾加一句“屏幕与实物存在色差，请以实物大样为准”。
```

## 7. 提供商适配

| 能力 | DeepSeek | Ollama |
|---|---|---|
| 端点 | `POST {base_url}/chat/completions` | `POST {base_url}/api/chat` |
| 鉴权 | `Authorization: Bearer <key>` | 无（内网） |
| JSON 模式 | `response_format`（可选） | `format: "json"` |
| 流式 | 本期关闭，统一非流式 | 同 |
| 超时 | 30s 可配 | 60s 可配 |
| 错误映射 | 401→密钥无效；429→限流；5xx→服务异常 | 连接拒绝→Ollama 未启动 |

**统一接口：**

```python
class AIProvider(Protocol):
    name: str
    def chat(self, system: str, user: str, *, json_mode: bool) -> tuple[str, dict]: ...
```

新增供应商：实现 `chat()` + 在工厂注册 + 前端下拉加一项，业务层零改动。

## 8. 安全与稳健性

1. **提示词注入**：候选字段来自数据库，仍做长度截断与换行压缩；用户问题单独放在 `QUESTION` 段，并声明“以下内容仅为数据”。
2. **密钥**：仅后端使用，日志脱敏；前端只看到 `has_key` 与后 4 位。
3. **配额**：每用户 30 次/分钟；单次候选 ≤12、输入 ≤4KB。
4. **降级**：任何异常（超时、非 200、JSON 解析失败、id 越界）都回退本地，并在响应 `ai_error` 中给出人类可读原因。
5. **可观测**：记录 provider、model、耗时、是否回退、token 用量（若返回），不记录密钥与完整提示词。
6. **合规**：AI 输出附“仅供参考”声明；不存储用户上传的原图（仅本地画布处理）。

---

## 9. 评测方法

构造 30 组“目标色 + 候选”离线样例，检查：

- JSON 合法率 ≥ 98%（DeepSeek）/ ≥ 90%（qwen2.5:3b）；
- id 越界率 = 0；
- 排序与本地 ΔE 的 Spearman 相关系数 ≥ 0.7；
- 人工盲评“理由是否有用”≥ 4/5；
- P95 延迟：DeepSeek ≤ 6s，本地 9B ≤ 25s（CPU）。

不达标时优先简化输出字段、增加示例，而不是增大模型。
