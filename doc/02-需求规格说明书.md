## 1. 项目背景与目标

毛布（绒面织物）的色彩沟通长期依赖实物色卡、微信群图片和口头描述，存在三个痛点：

1. **选色效率低**：客户发来参考图，店员靠肉眼在几百个色号里找近似色。
2. **色差扯皮多**：屏幕色、照片色、实物色三者不一致，缺少可量化的色差依据。
3. **商品信息散**：多个店铺、多个链接、多种材质，缺少统一的可检索色卡库。

本系统把“参考图 → 取色 → 色差匹配 → 商品与购买链接”串成一条闭环，并提供后台商品/色卡管理、AI 选色建议、新手引导，最终以 Docker Compose / Windows 批处理一键启动。

### 1.1 成功标准

- 新用户无需培训，3 分钟内完成一次“上传图片 → 取色 → 得到 3 个推荐商品”。
- 管理员 5 分钟内完成 20 个商品及色号的录入/导入。
- 同一颜色查询，本地算法与 AI 均能返回结果；AI 不可用时自动降级，不阻断业务。
- 普通用户权限（非 root）即可启动整套服务。
- 所有核心 CRUD 均支持单条与批量操作，列表支持全选。

## 2. 用户与角色

| 角色 | 说明 | 权限 |
|---|---|---|
| 游客 | 未登录访问 | 仅登录页 |
| 普通用户（user） | 门店选色员、设计师、客服 | 找色、推荐、浏览商品/色卡、查看自己的推荐历史、修改自己的密码 |
| 管理员（admin） | 店主/运营/技术 | 全部权限：商品/色卡/用户 CRUD、AI 配置、提示词、导入导出、系统设置 |

> 默认管理员：`admin / admin123`（首次启动可通过环境变量覆盖），登录后应在设置页修改密码。生产环境必须修改。

## 3. 典型场景（User Story）

- **US-01 找色**：用户上传一张客户参考图，用放大镜在图片上取色，得到 HEX，系统按 ΔE 推荐最接近的毛布商品，展示商品图、色号、色差、购买链接。
- **US-02 AI 分析**：用户对推荐结果不满意，点击“让 AI 分析”，系统把候选色卡与图片主色交给 DeepSeek/Ollama，返回排序理由与搭配建议。
- **US-03 维护色卡**：管理员新增商品，填入标题、店铺、价格、购买链接、商品图，并为该商品添加多个色号（名称 + HEX）。
- **US-04 批量整理**：管理员在商品列表全选当前页/全部筛选结果，批量上架、下架或删除。
- **US-05 配置 AI**：管理员在设置里切换 DeepSeek / Ollama，填写 Base URL、API Key、模型名，编辑默认提示词（skill），点击“测试连接”。
- **US-06 新手引导**：新用户点击侧边栏“新手指引”，intro.js 逐步高亮导航、找色、商品库、设置等区域。
- **US-07 数据导入**：管理员粘贴/上传 JSON 或 CSV，预览校验后批量导入商品与色号。

## 5. 非功能需求

### 5.1 性能

- 首屏（本地网络）≤ 2s；商品列表 1000 条内查询 ≤ 200ms。
- 本地颜色匹配 5000 个色号 ≤ 150ms（服务端内存计算）。
- 图片处理在浏览器完成，主线程阻塞 ≤ 100ms（使用 canvas + 防抖）。
- AI 请求超时默认 30s，超时/失败 1s 内回退本地结果。

### 5.2 安全

- 密码使用 PBKDF2-HMAC-SHA256（≥260,000 次迭代）加盐存储，绝不存明文。
- 会话令牌仅存 Cookie（HttpOnly、SameSite=Lax、生产 Secure），服务端存哈希。
- 所有写操作校验登录态与角色；管理接口仅 admin。
- 上传文件校验扩展名 + 魔数 + 大小，随机文件名，禁止路径穿越。
- API Key 使用 Fernet（AES-128-CBC + HMAC）加密存储，接口回显仅显示后 4 位。
- 登录限流、统一错误信息、CORS 白名单、安全响应头（CSP、X-Content-Type-Options、Referrer-Policy）。
- ORM 参数化查询，杜绝 SQL 注入；前端不使用 `dangerouslySetInnerHTML`。

### 5.3 可靠性

- SQLite 开启 WAL、foreign_keys、busy_timeout；写操作使用事务。
- 数据目录挂载卷，容器重启不丢数据；提供备份/恢复脚本。
- AI 通道故障不影响本地推荐；单点失败有明确提示。

### 5.4 可维护性

- 前后端分离，后端按 router/service/model 分层；前端按 pages/components/lib 分层。
- 模块间通过明确的 API 契约与类型定义交互，不跨层直接访问数据库/全局状态。
- 单文件 ≤ 400 行，复杂逻辑必须有注释与单元测试。
- 配置全部来自环境变量或 settings 表，不硬编码密钥。

### 5.5 兼容性

- 浏览器：Chrome/Edge 120+、Safari 17+、Firefox 120+。
- 部署：Ubuntu 22.04/24.04（Docker Compose v2）；Windows 10/11（Docker Desktop 或本地 Python 模式）。
- 架构：linux/amd64、linux/arm64。

## 6. 范围边界

**包含**：账户、商品/色卡 CRUD、图片取色、本地 + AI 推荐、AI 配置与提示词、新手引导、导入导出、Docker/Windows 启动。

**不包含（本期）**：
- 淘宝自动下单、支付、物流。
- 多租户 SaaS、复杂 RBAC（仅 admin/user 两级）。
- 实时协作、WebSocket 推送。
- 移动端原生 App。
- 供应商 ERP 对接。
- 自动抓取淘宝（受登录与反爬限制，提供导入器与登录态采集脚本，见文档 10）。

## 7. 约束与假设

- 淘宝店铺数据需登录态才能采集；系统以“可导入”为设计前提，当前交付库含 11 条真实毛布商品，另保留可选演示数据（默认关闭）。
- AI 能力依赖外部服务；离线环境仅本地算法可用。
- 颜色匹配仅作初筛，最终以实物大样与 ΔE 验收为准（业务免责声明需在界面展示）。
- 单机部署，预期并发 < 50，SQLite 足够；如后续扩容可平滑替换 PostgreSQL（SQLAlchemy 层已隔离）。

## 8. 验收标准（摘要）

1. `docker compose up -d` 后访问 `http://localhost:8000`，非 root 用户运行，健康检查通过。
2. Windows 双击 `start.bat` 可启动并自动打开浏览器。
3. admin 登录后可完成商品/色卡/用户的全套 CRUD 与批量操作。
4. 上传图片 → 滴管取色 → 本地推荐返回 ≥3 个商品，ΔE 与相似度正确。
5. 配置 DeepSeek 或 Ollama 后 AI 推荐可用；断网时自动回退且有提示。
6. 新手指引按钮可完整走完 6+ 步引导。
7. 全部后端单测、前端构建、E2E 冒烟通过（详见文档 09）。
