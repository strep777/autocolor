# 测试计划与验收标准

> 原则（按用户要求）：**所有代码与功能完成后才开始测试**。本文档先定义测试范围、用例与验收口径，开发阶段只写测试代码不执行，功能冻结后统一执行。

---

## 1. 测试范围

| 层级 | 工具 | 覆盖 |
|---|---|---|
| 单元测试 | pytest | 颜色转换、ΔE00、色系归类、密码哈希、提示词渲染、导入解析 |
| 接口测试 | pytest + httpx/TestClient | 认证、权限、商品/色卡 CRUD、批量、推荐、AI 降级、设置、上传 |
| 前端构建 | `npm run build` + `tsc --noEmit` | 类型、打包、体积 |
| 端到端 | Playwright | 登录、找色、CRUD、全选批量、引导、设置、AI 降级 |
| 部署 | Docker Compose | 构建、非 root、健康检查、卷持久化、重启 |
| 安全 | 手工 + 脚本 | 越权、注入、上传、密钥脱敏、CSRF、限流 |
| 性能 | 脚本 | 列表查询、匹配 5000 色号、首屏 |

**不测**：真实淘宝采集（依赖登录态，另见文档 10）、真实 DeepSeek 付费调用（用 mock + 可选手工）、多浏览器像素级差异。

## 6. 性能与安全验收

- 5000 色号匹配 P95 ≤ 150ms（`pytest-benchmark` 或脚本）。
- 商品列表 1000 条 P95 ≤ 200ms。
- 首屏 Lighthouse Performance ≥ 85（本地）。
- 越权矩阵：user 调用每个 admin 接口均 403。
- SQL 注入：`q=' OR 1=1 --` 不报错、不泄露。
- XSS：商品标题 `<img src=x onerror=alert(1)>` 原样显示，不执行。
- 上传：伪造扩展名被拒；文件名不可控。
- 密钥：日志、接口、前端 bundle 全局搜索 `sk-` 无命中。

## 7. 缺陷分级与出口标准

| 级别 | 定义 | 出口要求 |
|---|---|---|
| P0 | 崩溃、数据丢失、越权、无法启动 | 0 |
| P1 | 核心流程不可用（登录/找色/CRUD） | 0 |
| P2 | 次要功能异常、样式错位 | ≤ 3 且有规避方案 |
| P3 | 文案、间距、体验优化 | 记录待办 |

**发布条件**：P0/P1 全清；单元 + 接口测试通过率 100%；E2E 主流程全绿；Docker 验收通过；文档与实现一致。
