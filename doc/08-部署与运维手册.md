# 部署与运维手册

> 支持：Ubuntu 22.04/24.04、Windows 10/11、macOS（开发）
> 形态：单容器（FastAPI 同时托管前端静态文件）+ SQLite 数据卷；非 root 运行。

---

## 1. 交付物

| 文件 | 作用 |
|---|---|
| `Dockerfile` | 多阶段构建：Node 构建前端 → Python 运行时 |
| `docker-compose.yml` | 一键启动、数据卷、健康检查、非 root |
| `env.example` | 环境变量模板（复制为 `.env` 使用） |
| `start.bat` / `stop.bat` | Windows 一键启动/停止 |
| `start.sh` | Ubuntu / macOS 一键启动（可选，等价于 compose 命令） |
| `data/` | 运行期数据库、上传文件、密钥 |

---

## 2. 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `APP_PORT` | `8000` | 宿主机端口 |
| `APP_SECRET` | 自动生成并持久化到 `data/.app_secret` | 会话签名/Fernet 密钥派生 |
| `ADMIN_USERNAME` | `admin` | 首次启动创建的管理员 |
| `ADMIN_PASSWORD` | `admin123` | **首次启动后请立即修改** |
| `DATABASE_URL` | `sqlite:////app/data/plushcolor.db` | |
| `DATA_DIR` | `/app/data` | 数据库与上传目录 |
| `UPLOAD_MAX_MB` | `0` | 上传大小上限，0=不限制，由磁盘空间决定 |
| `AI_DEFAULT_PROVIDER` | `deepseek` | |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | |
| `DEEPSEEK_API_KEY` | 空 | 也可在后台设置 |
| `OLLAMA_BASE_URL` | `http://host.docker.internal:11434` | Linux 用 `172.17.0.1`、宿主机 IP 或远程地址 |
| `SEED_DEMO` | `false` | 全新库是否写入 24 条演示商品；真实数据请用导入 |
| `TZ` | `Asia/Shanghai` | |
| `PIP_INDEX_URL` | `https://pypi.org/simple` | 仅构建期；国内可换清华镜像 |
| `LOG_LEVEL` | `info` | |

> 生产建议：`ADMIN_PASSWORD` 用强密码；`APP_SECRET` 备份好（丢失会导致已保存的 API Key 无法解密）。

## 3. Docker 镜像设计

### 3.1 多阶段构建

```dockerfile
# ---- stage 1: 前端构建 ----
FROM node:20-alpine AS web
WORKDIR /web
COPY frontend/package*.json ./
RUN npm ci
COPY frontend/ ./
RUN npm run build

# ---- stage 2: 运行时 ----
FROM python:3.12-slim AS runtime
ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1
WORKDIR /app

# 非 root 用户（UID 10001）
RUN groupadd -g 10001 app && useradd -u 10001 -g app -m -s /usr/sbin/nologin app

COPY backend/requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY backend/app ./app
COPY --from=web /web/dist ./static
RUN mkdir -p /app/data/uploads && chown -R app:app /app

USER app
EXPOSE 8000
HEALTHCHECK --interval=30s --timeout=5s --start-period=20s --retries=3 \
  CMD python -c "import urllib.request;urllib.request.urlopen('http://127.0.0.1:8000/api/health',timeout=3)"
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000", "--proxy-headers"]
```

> 说明：不使用 root；`/app/data` 由卷挂载，首次启动自动 chown 兼容（见 entrypoint 说明）。

### 3.2 docker-compose.yml

```yaml
services:
  plushcolor:
    build: .
    image: plushcolor:1.0.0
    container_name: plushcolor
    restart: unless-stopped
    ports:
      - "${APP_PORT:-8000}:8000"
    environment:
      TZ: Asia/Shanghai
      DATA_DIR: /app/data
      DATABASE_URL: sqlite:////app/data/plushcolor.db
      ADMIN_USERNAME: ${ADMIN_USERNAME:-admin}
      ADMIN_PASSWORD: ${ADMIN_PASSWORD:-admin123}
      APP_SECRET: ${APP_SECRET:-}
      SEED_DEMO: ${SEED_DEMO:-false}
      OLLAMA_BASE_URL: ${OLLAMA_BASE_URL:-http://host.docker.internal:11434}
    volumes:
      - ./data:/app/data
    extra_hosts:
      - "host.docker.internal:host-gateway"   # Linux 访问宿主机 Ollama
    security_opt:
      - no-new-privileges:true
    read_only: false
    healthcheck:
      test: ["CMD", "python", "-c", "import urllib.request;urllib.request.urlopen('http://127.0.0.1:8000/api/health',timeout=3)"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 20s
```

### 3.3 数据卷权限

容器以 root 启动入口脚本，先把 `${DATA_DIR}`（默认 `/app/data`）交给 `app`（uid 10001）再降权运行 uvicorn，因此宿主机 `./data` 由 Docker 自动创建即可，**不需要 sudo**。

只有在宿主机预先创建了 root 所有的目录、又禁用了入口脚本时，才需要手动修正：

```bash
sudo mkdir -p data && sudo chown -R 10001:10001 data
```

若使用 rootless Docker / Podman，保持 `:U` 选项或预先 chown：

```yaml
volumes:
  - ./data:/app/data:U
```

## 4. Ubuntu 一键启动

```bash
# 1) 安装 Docker（已装可跳过）
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER   # 重新登录生效

# 2) 一键启动（普通用户，需已加入 docker 组）
cd /opt/plushcolor
chmod +x start.sh
./start.sh

# 等价的手动方式
# cp env.example .env           # 可选：修改 ADMIN_PASSWORD / APP_PORT
# docker compose up -d --build

# 3) 验证
docker compose ps
curl -s http://localhost:8000/api/health
```

浏览器访问 `http://<服务器IP>:8000`。

**开机自启**：`restart: unless-stopped` 已覆盖 Docker 重启；确保 Docker 服务开机启动：

```bash
sudo systemctl enable docker
```

## 5. Windows 一键启动

`start.bat` 逻辑（无需管理员权限）：

1. 检测 `docker` 命令；可用则执行 `docker compose up -d --build`，等待健康检查，打开 `http://localhost:8000`。
2. Docker 不可用：检测本机 Python，自动使用/创建根目录 `.venv`、安装后端依赖；缺少 `frontend\dist` 时先 `npm install` + `npm run build`，再以当前普通用户启动 uvicorn，监听 `0.0.0.0` 以便局域网访问。
3. 都没有：提示安装 Docker Desktop，或安装 Python 3.10+ / Node.js 20+。
4. 环境变量 `APP_PORT` 优先，其次读取 `.env` 的 `APP_PORT`，默认 8000；`data\` 由应用首次启动自动创建，不会改写 `.env`。
5. 结束时短暂停留；启动失败会 `pause` 并提示查看日志。

`stop.bat`：优先 `docker compose down`；本机模式下只结束命令行匹配 `uvicorn app.main:app --app-dir backend` 的进程，不会误杀同端口的其他服务；数据保留在 `data\`。

### 5.1 局域网访问（Windows）

1. 用 `ipconfig` 查无线网卡的 IPv4 地址，例如 `192.168.31.100`。
2. 浏览器访问 `http://192.168.31.100:8011`（端口以 `start.bat` 打印的为准）。
3. 首次部署需要放行入站端口（管理员 PowerShell 执行一次）：

```powershell
netsh advfirewall firewall add rule name="PlushColor LAN 8000-8020" dir=in action=allow protocol=TCP localport=8000-8020 profile=any
```

4. 让运行服务的电脑保持开机、不休眠；同一 Wi-Fi/局域网内即可访问。

> 安全提醒：局域网内所有设备都能打开登录页。请先把默认的 `admin/admin123` 改掉；需要跨网段/公网访问时，请在前面加 Nginx HTTPS，不要直接暴露 8000 端口。

`start.bat` 仍然不需要管理员权限；只有上面的防火墙规则需要一次管理员授权。

> 普通用户权限即可：Docker Desktop 安装时加入 `docker-users` 组；脚本不调用 `runas`/UAC。

## 6. 反向代理与 HTTPS（生产推荐）

Nginx 示例：

```nginx
server {
  listen 443 ssl http2;
  server_name color.example.com;
  ssl_certificate     /etc/letsencrypt/live/color.example.com/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/color.example.com/privkey.pem;

  # 分片上传：关闭请求体大小限制，避免 50GB 级上传被 Nginx 413
  client_max_body_size 0;
  proxy_request_buffering off;
  proxy_read_timeout 600s;
  proxy_send_timeout 600s;
  location / {
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
```

启用 HTTPS 后，应用检测 `X-Forwarded-Proto=https` 自动给 Cookie 加 `Secure`。

## 7. Ollama 接入

```bash
# 任选一个模型；CPU 机器推荐 3B 级别
ollama pull qwen2.5:3b
ollama serve          # Windows 托盘版通常已自动运行
```

- **模型名称无需手填**：进入「设置 → AI 助手 → Ollama」，填写服务地址后页面会调用 `/api/ai/ollama/models` 自动读取模型并填入下拉框；没有模型时按提示执行 `ollama pull`，再点刷新。
- 自动选模优先级：当前已选 > `qwen2.5:3b` > `qwen2.5` > `qwen3.5` > `qwen2` > `llama` > `deepseek` > `qwen3` > `qwen`。`qwen3` 系列默认 thinking，长提示下容易被思考 token 拖慢，不建议作为推荐首选。
- Docker Desktop（Win/Mac）：`http://host.docker.internal:11434` 直接可用。
- Linux：compose 已加 `host-gateway`；若仍不通，用 `http://172.17.0.1:11434`。
- 远程 / 局域网 Ollama：把设置里的地址改成 `http://<host>:11434`（或对方实际端口），点刷新即可看到对方模型；确保对方 `OLLAMA_HOST=0.0.0.0:11434` 且防火墙放行。
- 验证：`curl http://localhost:11434/api/tags`；页面显示「已读取 N 个本机模型」即成功。
- 首次加载 3B 模型可能需 5–20s，纯 CPU 生成更慢；`ai.timeout_seconds` 建议 ≥120（设置页最大 180）。GPU 可保持 40。

## 8. 日志、监控与备份

```bash
docker compose logs -f --tail=200

```

- 健康检查失败 → 查看日志中 `ERROR`；常见为数据目录不可写。

## 9. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 502 / 无法访问 | 容器未起或端口占用 | `docker compose ps`、`netstat -ano | findstr 8000` |
| `database is locked` | 并发写/磁盘慢 | 已开 WAL；降低并发，检查磁盘 |
| 上传 413 | 反代限制 | Nginx `client_max_body_size` |
| 上传 403 | 目录权限 | `chown -R 10001:10001 data` |
| AI 401 | Key 无效 | 设置页重新填写并测试 |
| AI 连接超时 | 容器访问不到宿主机 | 用 `host-gateway` 或宿主 IP |
| 登录后立即 401 | Cookie Secure + HTTP | 生产用 HTTPS，或关闭 Secure（仅内网） |
| 中文乱码 | 终端编码 | `chcp 65001`（bat 已设置） |

## 10. 安全基线

- 修改默认管理员密码；禁用不用的账号。
- 不将 8000 直接暴露公网，前置 HTTPS 反代。
- 定期更新基础镜像；`docker scout`/`trivy` 扫描。
- `data/` 权限 700；备份加密存放。
- API Key 仅存服务端，前端不可见。
- 关闭 Docker 的远程 API；`no-new-privileges` 已启用。
